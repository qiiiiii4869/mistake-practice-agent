## 使用

在项目根目录 PowerShell 执行：

```powershell
.\app\start-windows.ps1
```

1. 点击“登录智学网”，由教师手动登录；然后点击“读取考试列表”。
2. 在“全班逐题得分”中选择考试、学科和任教班级，点击“读取全班逐题得分”。单一选项自动选中，班级受学科约束。考试列表为当前学期第一页，最多 30 场。
3. 完整校验后保存到本机。若已有考试，需确认替换；失败或取消不会覆盖旧考试。
4. 扩展导入时，同时选中 `student-class*.json` 和同次 `verification-full*.json`。支持 BOM，单文件上限 16 MB；只接受完整全班得分，不接受三人样本。
5. 读取完整成绩并通过校验后立即保存本机历史，可选择“仅存为历史，保留当前考试”继续读取其他考试，无需先替换工作区。数据分析页查看各题得分率（可排序、点击查看学生）、学生逐题热力图，以及与本机历史考试比较的班级名次变化。进退步排除任一场缺考、0 分或无有效名次的学生。趋势折线展示本机所有同班同学科考试及当前考试的本班均分、年级均分、最高班均分；缺失值断线，重新读取对应考试可补充。考试按首次保存顺序排列，也可手动调整图中顺序。没扫和无原卷不判对错，不参与每题分母。
6. “生成报告”页的“本场教师设置”可保存变式数、每人上限、难度和部分得分阈值。全错始终计入；部分得分只有选择“纳入”且得分率严格低于阈值时计入。题数和难度供后续出题、组卷使用。
7. 重开程序自动恢复当前考试。“信息导入”页的“当前考试管理”提供“清除当前考试”，需确认，只清除应用存储，不删除扩展原始下载文件或智学网登录态。数据分析页以图表结束，不再附旧版按题统计表和完整学生逐题明细。

```powershell

npm ci

```

这是约 13 MB 的无开发服务器依赖 Windows 调试版，尚不是正式安装包。开发模式为 `npm run dev`，启动 127.0.0.1:1420 前端和 Tauri；正式优化编译为 `npm run desktop:build`，本次未运行正式发布编译。

依赖由 `package-lock.json`、`apps/desktop/src-tauri/Cargo.lock` 固定。Rust 关闭调试符号与增量编译，本次 `target` 约 1.62 GiB，C 盘剩余约 10.0 GiB。

## 代码与数据

- `packages/core/src/index.ts`：当前考试、学生、逐题结果、来源及教师设置模型；TS 导入审计、规范化、恢复校验和薄弱题统计。配对比较完整 summary，独立重算人数、题号、满分、分数、对错及汇总；拒绝失败、未处理完、重复标识、凭据和远程图片。
- `packages/zhixue/src/index.ts`：接口类型与提示信息。构建时直接复用根目录 `browser-probe/probe.mjs`，运行 `connect`、`subjects`、`export(fullClass=true)`。全班导出不包含作答原文、选项或答题卡图片。
- `apps/desktop/src-tauri/src/remote.rs`：内置窗口注入、轮询与清理，进度只有人数。普通读取超时 2 分钟，全班读取 30 分钟；进度不能证明成功，需保持智学网页面打开、不要中途跳转。
- `apps/desktop/src-tauri/src/storage.rs`：SQLite 保存当前考试及历史成绩表，事务替换、修订号冲突检测与结构复核，启用 secure_delete 和 DELETE 日志模式。历史只记录考试信息、三种均分及学生总分/满分/班级名次，不重复保存试卷与报告。重读同场同班同学科会更新同一条历史；清除当前考试同时删除该场历史，其他历史保留。清除应用数据不等同于擦除浏览器缓存、系统备份或磁盘所有残留。
- 当前考试保存在 `%LOCALAPPDATA%/com.local.mistake-agent/workspace.sqlite`，包含本场姓名和得分，属于本机应用数据，不放入项目目录。
- WebView2 登录资料保存在同一目录的 `zhixue-webview/`，可能保留登录态。密码由教师在官方页面输入，程序不导出密码、Cookie、令牌。
- 匿名诊断在同一目录的 `diagnostics/`：`tauri-login-verification.json` 记录连接状态；保存考试时写 `desktop-class-verification.json`，仅有计数与状态，不存名单、考试名或班级名。项目 `output/` 只存匿名证据。

## 窗口与网络边界

所有本机命令核对调用者必须为本地主界面。远程智学网窗口没有 Tauri IPC 权限。Windows 登录窗口使用独立资料目录和 `--no-proxy-server` 直连，不修改系统代理。首次沿用系统代理曾空白，独立直连后通过；空白页不能作为验证码或权限错误的结论。

顶层导航仅允许 HTTPS 智学网域名及官方登录页引用的 `open.changyan.com`，禁止新弹窗。导航检查不等于所有子资源网络白名单，完整出站限制仍待后续网络管控实现。本次通过不能保证以后不触发验证码；遇到 60500 可改用 Chrome 扩展导入。

当前只采集得分，不能提供错误选项分布或确定具体错因；选项统计需另补数据来源。试卷照片与题号也仍待关联。

### 当前空白卷流程（2026-10-26，替代早期单页手动识别流程）

上传 JPG/PNG/WebP 空白卷时只检查文件并保存到本机，不识别、不调用模型。教师准备知识库并配置本机会话模型密钥后，确认空白卷不含学生姓名，点击“生成结果”。Agent 才逐页读取、独立再次读取核对题号/完整题干/选项/共用材料，再检索知识库、分析知识点、出补练题并独立解题。无需提前手动录入或逐题勾选。手动修正入口折叠保留，最终生成题仍需教师审核。

两次读取不是正确性保证：低置信度、警告、内容不一致、失分题缺失、保存失败或额度不足会停止，不继续猜题或付费调用。通过的核对题干先保存到本场，生成结果可另行审核保存。两次卷面读取均计入模型用量；上传本身不消耗模型 token。109 项 TS 测试及模拟界面流程通过，尚未使用真实图片调用付费模型。

上传支持 JPG/PNG/WebP、PDF 和 Word `.docx`，上传只保存原文件。点击生成时在本机将 PDF/Word 展开为图片页，再进入读取核对流程；不上传整份原始 Word/PDF 给模型。最多 30 个文件或页面、编码合计 8 MB，展开后最多 30 页。旧 `.doc`、外部资源、嵌入对象及暂不支持的旧式图形请先另存 PDF。Word 版式可能与 Office 有差别，真实 Word 样本尚待验收。渲染使用本地 PDF.js、[docx-preview](https://github.com/VolodymyrBaydalka/docxjs)、[html-to-image](https://github.com/bubkoo/html-to-image)。

用户要求实际验收必须用其提供的 50 人考试及确认的空白扫描卷，模拟测试不能替代验收。实际只读核对为 46 人有得分、4 人无原卷、598 条逐题记录；4 页原始扫描 PDF 已用实际转换代码展开，未调用模型、未改原考试。卷面重复题号已由教师确认排除第二道第 5 题，其余题号不顺延。知识库为空；教师要求先不做全流程验证，当前已暂停，未调用模型，因此未记作端到端验收通过。真实资料与转换图片仅保存在应用本机目录，不进入仓库。

空白卷重复上传按内容自动跳过，已保存文件直接显示在上传区；大小或格式限制会分别说明，不再笼统显示导入失败。真实扫描 PDF 的首次上传、重复跳过及刷新保留已验证，未发起模型调用。

### 升级后的旧版考试恢复与生成准备

登录云端软件账号后，在空工作区使用“检查旧版考试”，核对摘要并输入当前用户名，可把旧根目录考试复制到该账号本机目录。不会覆盖已有考试，不移动或删除原库，不迁移密码/登录态，不上传学生数据。已存在考试的账号不能使用此入口覆盖；源或目标版本变化需重新检查。

真实生成前会检查当前账号的本机知识库是否有可检索文字、试卷、失分题和模型配置；缺少知识库时在预占次数与识别之前停止。也可使用“检查生成准备”单独检查，不调用模型或扣次。检查通过不代表题号对应或生成质量已验收。

`tools/storage-check/src/bin/check_legacy_real.rs` 接收真实旧版数据库路径，只读源库并在系统临时目录验证复制完整性、防覆盖、版本检查和知识库就绪状态；仅输出汇总，不输出学生姓名，退出清理临时副本。实际账号恢复必须通过登录后的确认入口，不按用户名猜 UUID。

### 阶段 A 第二批：内容规则、失分分配及教学证据

新增 `workflow/validators.ts`、`assignment.ts`、`teachingEvidence.ts`，仍为未接入界面的纯业务模块。听写拒绝模型自报检查状态，parts 必须还原已核对知识句，盲填请求不带答案；出题区分单/多选、简答、计算，校验原题/目标/材料来源，独立解题请求不含答案/评分点。选择题比集合，计算题仅支持带显式单位及容差的单数值，简答需独立评分点比较结论，未提供适用比较策略不会通过。复杂公式/多步计算与开放答案的全面验收尚未实现。

分配前冻结目标，失败内容不缩减覆盖率分母；跨模式/旧输入池拒绝复用，没扫/无原卷不分配，原始失分题始终保留缺项。教学证据从实际得分计算，题号和人数去重，零分参与、无效记录不进分母；无可靠知识点映射时明确未映射，不能从得分断定个人错因。

`node tools/check_workflow_content_real.mjs <实际账号数据库路径>` 只读核对真实成绩聚合、无映射/无内容时的缺项与模式隔离；内容规则示例来自已批准实施计划，未把示例挂到班级知识点上。没有调用模型、生成真实练习/PDF或修改数据库；阶段 A 整体仍待 runner、教学建议与完整离线内容路径接线。

### 阶段 A 第三批：调度与内存检查点

`workflow/runner.ts` 以注入的阶段处理器驱动固定状态机，不依赖 React。`checkpoint.ts` 提供账号/任务键控的内存存储、版本冲突检查和单账号执行互斥；返回值用结构化副本隔离，拒绝 Key/凭据/请求头、函数和非 JSON 状态。调用前先记请求摘要与预算，未知用量占住预留；未知请求结果不自动重放；未知 stage 副作用需先核清。等待中的调用结束前不释放执行锁。

PDF 与结算需要专门的结果证明事件；结算回包丢失只恢复 settling，不重跑已经记录的步骤。处理器、云端授权、真实 QA 和持久化仍待接入，这些协议守卫不构成实际成功证明。当前是内存检查点，不代表已有正式断电/跨进程恢复能力，也未替换产品现有生成路径。

`workflow/teachingAdvice.ts` 增加不调用模型的确定性回退报告，统计只能由冻结原始成绩计算，无映射时不生成知识点诊断。`node tools/check_workflow_runner_real.mjs <实际账号数据库路径>` 使用真实成绩，只读核对报告与内存存储，并通过受控回调演练并发、取消和未知结果禁止重放。回调演练不连接真实云端/模型、不生成真实题目/PDF。
