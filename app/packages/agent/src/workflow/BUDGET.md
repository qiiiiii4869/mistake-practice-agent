## 本次问题与修正

本机只读核对的考试规模为50人、13个成绩题号、上传PDF4页，未修改原数据库或调用识题服务。旧式上界`3P + 4U + 12U + 2 + 8`将每题独立提炼/核验及其修复都预留，得到230，因此在生成前拦截。

整卷超过6个原题单元时，提炼和事实核对改为每组最多6个单元，按原unitId分别返回，单元内部仍最多3个事实。最初上界为`3P + 4ceil(U/6) + 12U + 2 + 8`，13题/4页为190，15题/4页为214。获准任务的实际请求仍逐次预留并检查已授权上限；上述数字是计划上界，不是实际用量或扣费金额，也不能保证所有异常都能在此数内完成。

分析仍全班共用，不按50名学生逐人重复识题。已核验事实先合并、个人目标按失分排序/上限选择，内容池只生成被选中目标；同一知识点的内容可分配给多人，不为每个人重新调用模型。

## 分阶段保护

- 识题仍每页独立读取，最多3次；不降低识题或独立解答标准。
- 识题后按实际原题文字和32000字节请求上限保存提炼分组，调用前重新核对剩余预算。单题超长不截断，停止并保留原文。
- 提炼结果按原题单独检索资料，核验时根据实际知识句/资料长度另存分组。资料不跨组借用；阶段前核对核验、有限修复与候选内容所需余量。
- 通过的事实保留。只把失败事实送去一次定向修复，再独立核验一次；未知unitId、重复ID和非法单项不能进入可靠映射，原始未覆盖题仍保留。
- 个人目标确定后，依据实际去重目标重新核对剩余内容预算，扣除已经完成的调用/检查点。分组、取消、重启或重试不会重置原调用数、Token预留或截止时间。
- 计划或Token仍超限则进入可恢复状态，不自动抬高已授权额度，不裁掉题号或学生后宣称成功。旧版不超过6题的逐题/局部测试路径保持原协议。

分组计划持久化，未完成批次的请求响应也写入原调用账本。恢复时从步骤基线重放已保存响应，不重新支付已确认调用；未知请求仍要求用户明确决定是否重试。
