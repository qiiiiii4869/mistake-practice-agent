# 双模式工作流 · 业务核心与云端模型接线

2026-10-28 实现。入口为 `index.ts`，与旧版 `AgentBatch`、人工审核及计次流程独立。

阶段 A 实现纯业务核心与固定流水线；后续已接云端共享 Key 和真实模型、阶段 B PDF 离线执行器，以及阶段 C 的 SQLite 任务保存/重启恢复（见本目录 `PERSISTENCE.md`）。`live.ts` 通过受控 Rust 命令授权、调用和结束任务，不在 JavaScript 接收 Key。`contentReady` 仅表示内容就绪；桌面整场交付入口及正式计次继续按阶段 F 接入。

## 真实内容测试

### 第11题听写收尾（提示词v10）

知识句原词自动保留在acceptedAnswers中，避免仅有同义表述时整条被误拒。双空中某空泄露/删除条件时可恢复其可见原文，保留另一合格空及模型别名，仍完整校验与独立盲填；错误还原、重复空号或两轮后盲填不一致不放行。备用逻辑优先知识候选，数量量词保留在题面、只挖核心术语；失败后优先知识点名称中的合法词段，拒绝泛用动词和开放式举例。数量、方向和条件不作为同义差异合并。

提炼优先可复用的单一学科命题，背景不重复结论；事实核验逐字检查概念类别、修饰关系和因果链，不把“能猜出正确意图”当准确。最终从真实第11题原卷重新OCR到内容完成，10次真实调用、9816Token、未知0，3事实/3条听写通过、分母3、覆盖率1、skipped为空。此前中间机器全过结果经人工开发复查发现过程/产物混写，强化核验后重新全程运行才记最终验收。学生成绩为合成，不是整班或PDF验收；旧响应不复用，原文不入Git，模型未来随机输出仍须逐次校验。

### 当前读取范围：只读正文（提示词v9）

负责人进一步限定只读取题干文字。保留共用题干、各小问正文/编号和原始答题空白，不读取图示或表格，包括杂交图中的P/F₁/F₂、比例、性别符号、箭头、图注及表头/单元格。模型旧响应中的figure/tables元数据均不保留。提炼与核验只使用剩余正文，不把空白当事实、不猜图表；需要图表的小问跳过，其余独立文字知识点可继续。此范围替代下方v7“文字材料”的较宽表述。

原第11题旧识题真实复现：杂交图箭头/图注混入stem，表格有时按行转写、有时按列改写，造成三次整段不一致。v9明确上述区域均跳过，所有原题空白统一________；程序只将连续下划线长短视为排版差异，仍严格区分数字、大小写基因、显隐性、否定、上下标和小问缺失。原始正文保留，不直接删掉不一致实质内容放行。

最终OCR以paragraphs数组返回普通正文段落，程序按序拼接；兼容旧stem，但同时返回两种矛盾正文则拒绝。图表边框内注释与孤立图名不属于正文。提炼不要求先解出原题空白，应保留正文明确的独立知识命题，仅图表依赖的目标跳过。

第11题最终分步验证：2次全新正文OCR一致且排除图表/图注；随后复用这2份私有读取结果，重新真实提炼、核验与听写12次付费调用，3事实通过、1条听写通过、2条仍未过，整体partial。旧stem方案曾2条通过但残留图注，不作为最终读取范围验收。不能称最终版本整题全部成功或全新端到端；成绩是合成夹具，正常日志无原文，原始诊断只在私有目录。

### 逐项事实核验与修复（提示词v8）

通过事实立即保存并保持factId，仅将未通过候选与accurate/supported/inScope结果送回extract的repair，再核验修复候选。修复数量/顺序必须匹配；结构错误或空结果仍保留此前通过项。未修复事实标partial与fact_check_failed，不能被成功的另一事实掩盖。每单元2次提炼和2次核验总限额不变，异常不会无限重试。verifyFact诊断只记三类拒绝代码或结构错误，不保存正文；核验已修复与后续挖空失败分开归类。

2026-10-28第3题全新真实回归：14次模型调用、24701Token、未知0，首轮3个事实中2个通过，只修复核验余下1个，最终3条听写全部独立盲填通过、contentReady。此前同题一次新OCR因“如图/如下图”和明确比值区间连接线差异隔离，增加受控格式兼容后重新读取；仍保留原文并区分数字、负号和图示标签。不复用旧识题/提炼/核验响应，成绩使用合成夹具，尚不构成真实整班报告或PDF验收。

### 当前策略：只读题干和选项文字（提示词v7）

按2026-10-28最新要求，忽略题内图示、图中标签/数值/关系。扫描卷仍经视觉接口读取印刷文字；figure字段即使由旧模型返回也丢弃，不参与对齐。提炼与核验只接收正文、选项和共用文字材料，不带原始页图；Rust同时移除旧图示元数据并拒绝非识题阶段的图像输入。本节替代下方v4的图形证据实现。

仅保留无需看图即可核验的知识点；全部依赖图示或文字不足时允许facts空数组，记录text_evidence_insufficient并保留原始失分题，不调用后续核验/生成。独立核验不能把干扰项或缺失图示推测当成文字依据。

v6真实任务曾在verifyFact因推理加结构化输出超过4096而截断。v7的verifyFact/blindFill/solve为16384，其他阶段4096；TS保守预留16384，Rust按payload上限预留，云端v7策略同步；整体预算、修复次数和截断拒绝规则保持不变。

此次第3题从新OCR开始共10次真实调用，提炼核验3个事实、1条听写通过；另2条因答案可见/限定条件挖除被拒，整体partial。没有缓存替代真实调用，也未再截断；这不代表所有内容通过。成绩使用合成夹具，原文只留私有诊断目录，临时测试账号已清理。下方较早版本条目保留实现历史。

### 必要背景与独立推理（提示词v6）

提炼结果可带context，保留题目自定义术语、材料机制和必要前提；条件未在知识句/背景中出现时补入背景，再与知识句一起独立核验。核验要检查离开原卷是否可理解。背景随听写展示并传给盲填，任何空位答案及受控同义词在背景中出现都拒绝该空位；不同背景或条件不合并事实。出题阶段也接收已核验背景。

方向类候选优先用程序生成最小单空，保留变化对象。盲填接收一份带空句、context和每空的change_direction/term格式，不接收标准答案、可接受答案或纠错。方向词仅匹配受控的完整同义项，不自动混同增减、不变、数值程度；实质歧义仍拒绝。Rust对verifyFact/blindFill/solve启用推理，max_tokens仍为4096，使用原有预算、超时及有限修复上限。

2026-10-28真实回归针对用户截图同一失败知识句：复用此前可信识题，恢复失败句并补原卷背景，重新事实核验和盲填后1条通过。该记录不是全新识题/提炼端到端，也不是整班报告验收；学生得分使用合成数据，原始回包只留私有诊断目录，临时云端测试账号结束后删除。

### 教师报告的生成时点（提示词v5）

单题/局部测试只测试识题及听写/出题，`teacherReport=null`、`advice=[]`，状态机跳过写建议阶段，不进行任何guidance调用。界面的“本次测试统计”仅为检查依据，不是教师报告。完整考试流程在所有内容处理、个人分配与全班统计结束后一次生成ClassTeachingReport，包含整体观察、优先讲评重点、匿名分组巩固和统一后续检查，不逐题分别写教师建议。

报告输入包括全班逐题正确率、完整知识映射和ClassOverview：总分均分/中位数/离散度及得分率分布，每个非空分数组也有逐题正确率。模型只组织文字，数字从同一冻结数据插入；零分与缺失记录严格区分，分数组不是能力等级。生成结果须引用有效证据和所有非空分数组，失败有限修复后用综合模板回退。完整报告的普通用户入口与PDF仍待后续整批流程接入，不能把单题测试拼成完整诊断。

失败摘要只列当前未通过目标及识题缺项；最终已通过的目标，其早期失败移动到默认折叠的“已修复的校验记录”，不计入当前失败。校验与覆盖率规则不变。

### 图形证据与挖空格式兜底（提示词v4）

识题的stem只含印刷正文，figure单独标记图形存在及实际标签，不把模型自行解释的图注放进stem。两次正文和图形存在标记一致才采用；图形标签取一致共同项，不依靠自由描述确认图形事实。SourceUnit保留原始pageIds，Rust在extract/verifyFact时从本任务授权页面内取原图附给模型；没有原图不允许图形事实请求。原图不会给独立盲填，也不会发送到账号服务器；图像请求在两端预算中预留用量。

模型挖空JSON失败时，程序可从已核验知识句构造单空parts，仍须可还原、条件保留、答案无泄露和独立盲填通过。模型可在知识句内选择其他明确关键词，不能选择句外内容。发生盲填失败时，修复带失败代码及应避开的空位；第二轮不得不加修改地复用同一歧义空位。程序可从同一句取另一词段，但不新增事实、不添加无限语义判分。受控术语同义写法集中于answerAliases.ts；第一/第二次分裂、前/中/后期和额外说明不自动混同。

开发用recognition_probe/workflow_probe只在显式运行时使用stdin传入的临时测试会话，经正常HTTPS授权，在Rust内持有Zeroizing Key；它们不打包进桌面程序。图文原始诊断保存在账号私有目录，普通workflow-runs仍仅保存无正文摘要。真实检查与合成回归须分开说明，不能把分步缓存验证写成全新端到端验证。

### 部分完成与本机诊断

识题阶段独立保存`recognitionChecks`：题号、页序、各轮返回数/置信状态/警告数量和判定原因，不含转录原文。`recognition.ts`要求至少两次可信读取得到相同实质内容；第三次传focusNumbers定向重读，只进行一次且仍独立。只兼容受控的标点/选项格式差异，数字、单位、否定词、上下标和真实内容差异仍隔离；含糊或当前题警告不放行。识题原文先作为资料，不在此时要求所有公式都能排入PDF，最终生成条目的公式限制保持不变。提示词版本v3，Rust接受旧版本以兼容已发客户端。

同一道原题可以映射多个知识目标；其中两个条目通过、一个失败时，已经通过的内容保留，未覆盖目标仍在原分母中。整体是否 partial 按个人目标覆盖门槛判断，不能仅根据原题号在失败摘要中出现就说整题没生成。界面同时显示知识点名称、有效条目、未覆盖目标以及具体规则失败原因。

`validationAttempts` 保留每轮结构/盲填/独立解题拒绝原因，异常仍按原规则有限修复。任务结束后先清理Rust中的Key，再调用 `workflow_save_diagnostic` 把 `workflowAudit` 的白名单摘要写到账号目录 `diagnostics/workflow-runs/<runId>.json`。日志不含Key、账号/学生标识、题干、知识句、答案、模型原始输出；调用数和usage总数由Rust复核，支持下次查日志，无需程序一直开着。旧版本没有保存的具体失败原因无法事后补出，必须由新版运行后产生记录。

“生成报告”页的新入口使用 `CloudWorkflowPanel.tsx`。管理员配置云端 Key，普通用户选择听写/出题、1～6个原题号及所需卷面页码（默认一道题和第一页）。PDF/Word 在本机展开，不改原考试；空知识库合法。原卷两次独立读取，最多追加一次重读；有歧义隔离，不伪造教师确认。已确认重复题号可在开始前指定保留第一次，否则隔离；不重编号。

测试范围写入冻结输入并参与缓存键；范围外失分题列为 outOfScopeNumbers，测试统计保留完整考试分母与未映射题数，但不生成教师报告，不能把局部测试称为全卷诊断。识题请求也进入调用账本，未知图像用量保守预留。真实调用只使用固定阶段，Rust 再检查结构、独立解题载荷、匿名、任务归属、预算与授权。

任务正常/部分完成/失败/取消都会调用 release。此入口没有正式 PDF，暂以 partial/failed/cancelled 释放预占，不自动扣成功次数。Rust 先清除 Key 再请求服务端；页面不接收 Key。刷新后若云端仍有预占，可用“释放未完成云端任务”。生产新接口已于2026-10-28部署，真实 Key 尚未配置；合成测试和公网鉴权检查不代表真实模型效果。

## 使用方式

```typescript
import { freezeInput, runWorkflow, MemoryWorkflowStore } from './index.ts';

const input = await freezeInput({
  ownerId: 'local-account-id', workspace, mode: 'dictation',
  knowledgeRevision: 'empty', settings: { maxItems: 16 },
});
const result = await runWorkflow({
  input, runId: crypto.randomUUID(), signal,
  ports: { model, store: new MemoryWorkflowStore(), prepareUnits, retrieve, onProgress },
});
```

存储实例由会话服务持有，多次调用复用同一实例。`prepareUnits` 是本机资料展开和识题的依赖接口，本阶段由合成结果代替，不能把此接口已接好描述成真实识题已完成。`retrieve` 返回最多六条 `{documentId,page,text}`，空数组合法；不上传文档名称、学生姓名、名单或账号。

`GenerationMode` 为 `dictation/exercise`，`ExecutionMode` 为 `mock/real`，与旧 `AgentBatch.mode` 分开。原始工作区经校验后复制，旧出题结果不进入冻结输入；调用者随后修改原对象不会改变正在运行的输入。

## 检查与调用边界

教师建议按“全班逐题正确率→该题知识点→讲评重点”生成。`EvidenceSummary.questions`保留全卷原题统计，每题正确率为全对/有效作答人数，部分分单列，真实零分计全错；没扫/无原卷和满分为零不计入。个人补练设置不缩减教师统计分母。KnowledgeEvidence中的questionStats保留逐题数据，按相关题的低正确率挑讲评重点；得分率是辅助指标，不能把多题加权得分率当逐题正确率。未映射题保留正确率但不虚构知识点，局部测试不能称为全卷诊断。提示词v2体现该口径，当前60%仅为开发优先级初值。

- 完整知识句先独立核验，再挖空；`parts` 必须逐字还原原句。盲填请求不包含完整知识句、答案、可接受表述和纠错说明。
- 独立解题只接收题目、必要原题材料和目标范围，不包含生成答案、解析、评分点或计算结果。
- 单选/多选比较规范选项集合；计算比较数值与相同单位，固定相对容差 `1e-9`，不执行模型代码或进行任意单位换算；简答采用独立评分点的显式匹配，无法确认的自由表述保守拒绝。更丰富的单位与语义规则待真实模型适配时扩展。
- 中文/LaTeX 沿用现有 PDF 模块的受控转换；不支持的公式不能作为合格内容进入下一阶段。
- 成绩统计保留真实零分，排除没扫、无原卷及满分为零的记录；一题多知识点只称“相关题表现”，各行人数不能相加当全班总人数。
- 教师建议文字不得自行填数字、比例或原题编号，显示数值由后续模板取证据表插入。模型文字检查目前是结构与保守规则检查，不能保证检测一切无依据叙述。

## 预算、恢复与缓存

初值只用于开发，待真实资料校准。超过六个单元的整卷已按最多六单元分批提炼/核验，初始计划上界 `3P + 4ceil(U/6) + 12U + 2 + 8`，并按实际文字长度、知识句和选中目标分阶段复核。200次/200万Token硬上限不变，计划超限不裁目标，恢复不清空账本。局部测试/小规模逐题路径保留原协议。详见 [整卷分组与调用预算](BUDGET.md)。

每个模型请求先写调用记录并预留 UTF-8 输入字节数加最大输出 Token 数；返回 usage 后按实际值记录。usage 缺失或请求中断保持预留，不清零。文本请求超时暂停，外层取消即终止等待并通知模型依赖的 AbortSignal；忽略迟到结果。只有明确的 `workflow_network_error` 最多重试一次，并受全局八次限制，鉴权与余额错误立即停止。

同账号同一时刻只能运行一个任务；同 runId/contentHash 重复点击共享 Promise。完成的同任务读取缓存，不再次生成。继续未完成任务须显式 `resume:true`，原预算与截止时间不重置；有未确认调用须由调用方明确处理后使用 `retryUnknownCalls:true`，不自动重发。此选项只是允许在剩余预算内继续，不保证供应商不重复计费。

`MemoryWorkflowStore` 留作纯业务测试；桌面已使用 `SqliteWorkflowStore`，支持账号隔离、输入冻结、结果/用量事务、步骤重放、执行租约、完整性复核及跨进程恢复。未知请求必须明确选择是否重试，原预算与截止时间不重置；阶段 B 文件执行器可同步保存导出配置与失败状态并重试。正式结算失败恢复仍待阶段 F 接线。

共同分析缓存要求模型依赖显式提供 `cacheKey`，标明配置版本；缓存按账号、考试/学科、试卷内容、题号、资料版本、模型配置、工作流/提示词版本隔离。只缓存没有隔离/失败项的共同识题与事实结果；跨模式可复用，仍重新选择个人目标、生成模式内容。教师综合报告只在完整考试流程最后生成。无 `cacheKey` 时关闭跨任务分析缓存。同任务复用也检查模型配置。

`exportProfile` 建立独立导出设置与摘要，改变分开/合订或答案组织不调用模型。阶段 B 的 `buildDocumentPlan` 与 PDF 执行器已实现文档计划、逐页 QA 和新目录提交，输出 `exportStatus=verified` 与 `settlementStatus=not_requested`；不修改本模块的 `contentReady` 为正式计次成功。
