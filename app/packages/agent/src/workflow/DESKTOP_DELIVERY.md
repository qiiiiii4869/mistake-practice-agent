# 全班生成与桌面 PDF 交付

2026-10-30：生成报告页面新增默认显示的“生成学生练习与教师报告”。小范围云端测试和旧版手动审核工具收在折叠区，保留已有功能。

## 用户流程

1. 导入本场考试和无学生姓名的空白卷，可选导入PDF知识库。
2. 选择听写/变式补练、每人数量上限、难度、每人一份/全班合订，以及是否附答案页。
3. 点击“生成并导出 PDF”。本机先检查导出组件与系统字体，再展开整份试卷、冻结所有题号和个人目标；没有testScope，也不要求手工逐题审核或输入个人Key。整场结束后生成独立教师报告。
4. 内容完整通过后选择保存位置，逐文件编译、逐页解析与渲染QA，通过后新建最终目录。教师报告始终单独保存；无错题/缺卷学生保留相应状态页。
5. 选择位置时取消，内容仍保存到当前账号任务库；稍后导出不重新调用模型。导出失败/取消可从保存记录重试，组织形式与答案设置改变只建立新导出配置。

结果页保留未覆盖目标/原题与失败摘要。部分完成、单题测试、模拟任务不能冒充全班正式PDF；预算超限在调用前停止，不截掉原题后声称处理整场。当前保守调用估算仍有限，不能承诺所有80题规模可运行。

## 实现

`ClassWorkflowPanel.tsx`连接现有整场runner与SqliteWorkflowStore。`workflow_pdf_status/export/cancel`由Rust校验当前账号，只从该账号workflow.sqlite加载任务；renderer不能传入原始任务、编译器或任意输出路径。新导出通过原生目录选择器取得目标；重试只接受已保存exportId。

`workflow_export_process.rs`仅启动随包Node与固定bridge脚本，清空继承环境，只保留系统目录/临时目录变量。子进程的数据库RPC仅允许同账号同runId的load/load_response/list_exports/save_export，不能修改生成账本、账号权限或调用模型。进度通过本机事件返回；取消通知AbortSignal并给有限清理时间，超时回收子进程。

Node桥复用已经验证的PDF执行器及逐页QA worker。导出前重新加载并校验保存内容及独立解答回执，mock/局部/未完成任务拒绝。任务库保存导出配置、失败状态和成功证据；engine请求摘要改为canonical序列化，避免Rust SQLite读回字段顺序变化导致“pdf_stale_staging”。

最终交付在`report-<exportId>`目录。其父目录的`.workflow-work`是包含冻结输入、答案和重试记录的本机私有缓存；分享材料时只分发最终report目录。

## 打包

在Node >=24.16和PowerShell 7环境执行`npm --prefix app run prepare:runtime`，或使用`app/build-portable.ps1`。准备脚本复制固定源目录与锁定的xstate/PDF.js/canvas依赖，并附Node二进制、对应版本许可、版本及摘要清单，不复制账号库、环境配置、模型Key或学生数据。无需用户另装Node，不复制系统字体。

`test:workflow-desktop-export`先构建原生测试探针，检查真实打包运行时的听写/出题、个人/合订、教师文件、重开重导出、模拟任务拒绝和取消。`check_class_workflow_ui.py`验证全题号范围、设置、缺资源提前停止、PDF失败重试、取消选择位置和不扣次数。真实模型质量仍需另行验收。

## 结算与边界

当前这条流程生成、校验并交付文件，**不请求成功结算**。保留`settlementStatus=not_requested`，UI明确“次数结算尚未启用”；模型调用仍消耗供应商额度。云端任务按现有非成功结果释放/暂停，不能把客户端PDF检查当作可信收费完成。成功计次、完成证明、断网结算重试仍属于后续工作，不在本批绕开服务器完成门槛。

本批只做合成IPC、隔离数据库、实际PDF文件和原生子进程工程验证，不调用真实模型、不改线上服务或账号次数。图题能力和实际整班内容质量不因接入页面而视为已验收。
