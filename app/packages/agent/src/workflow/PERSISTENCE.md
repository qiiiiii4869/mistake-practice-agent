# 阶段 C：任务持久化与恢复

`SqliteWorkflowStore` 实现 `WorkflowStore`，桌面通过受限的 `workflow_store` IPC 调用真实 Rust SQLite 模块。Rust 从当前已验证的软件账号推导 `accounts/<账号ID>/workflow.sqlite`，不接受外部路径；调用前后均检查当前账号，跨账号或失效会话不得返回旧任务数据。现有 workspace/knowledge 数据库独立，替换或清除当前考试不会删除工作流档案。

## 存储与完整性

共享 `schema.sql` 定义冻结输入、任务、调用结果、共同分析缓存、执行租约和导出配置表。开启外键、WAL、FULL 同步和安全删除，数据库初始化在事务中进行；未知数据库标识/较新版本拒绝打开。完整运行状态及 XState 快照保存为带 SHA256 的 JSON，试卷图像只在按 contentHash 去重的冻结输入中保存，不复制进每条模型记录。

冻结输入由 TypeScript 规范序列化并计算摘要，Rust 再检查规范串的实际对象及 SHA256。读取时核对 JSON 摘要、账号、版本、调用行与主快照的一致性；TypeScript 再检查题目、知识句、自检结构、个人分配、教学统计和建议引用。通过的听写/补练还必须找到同一请求摘要的独立盲填/解题实际结果，重新比对，不能仅信任 `passed:true`。

写操作使用 SQLite 事务、递增 revision 和账号执行租约；同账号不同进程不能同时调度。租约每十秒续期、三十秒到期，旧执行器的迟到写入被拒绝；进程异常退出最多等待原租约到期，不能强行覆盖仍在运行的任务。前端丢失租约立即终止调度。模型 Key、密码、Cookie、请求头或令牌字段在 Rust 递归拦截，Key 只存在原有 Rust 临时内存，不进入 SQLite 或 XState。

## 调用事务与崩溃恢复

调用前保存 callId、请求摘要、阶段、作用域、次数及预留预算；调用后将原始结构化返回和已知用量与调用状态一起写入事务。已完成但隐私/结构拒绝的返回不保存正文，只保存受限错误代码。原始返回属于本机账号私有资料，不写匿名诊断或 Git。

每个业务检查点先保存基线与起始调用序号。若关闭发生在“返回已提交、整个步骤尚未提交”之间，恢复该步骤的基线，按固定请求摘要重放已提交结果，不再次访问模型。原来的修复轮次、失败记录、选题分母和调用上限均保留；检查点最终完成后删除临时基线。

未知/进行中请求不自动重发。界面显示可能已产生模型费用，用户明确勾选后才允许使用有限第二次尝试；旧未知请求及其预留预算继续保留。已经有成功第二次结果的请求可直接重放，不再要求重复确认。请求摘要对不上、已完成结果缺失或校验失败时停止，不猜测恢复。

原始 startedAt、总时间上限、调用数、已知/未知用量和每阶段上限都不重置。已完成内容可以跨时间查看和重导出；未完成内容超过原截止时间不能继续模型调用。

## 云端与桌面

“生成报告 → 云端模型 · 双模式内容测试 → 本机已保存任务”列出本账号的任务、阶段、调用数及未知请求数。查看已保存结果不领取 Key、不调用模型；恢复时核对当前考试 revision、知识库 revision、模型配置与提示词版本。成绩/试卷/设置/知识库/模式变更应新建任务；旧结果仍可查看。

暂停或关闭清理本机 Key，并保留未结束云端 jobId/requestKey；继续时用同一请求身份重新核验授权。服务器摘要新增已用调用数和 Token，Rust 取云端计数与本地账本保守占用的较大值，并保留原截止时间；不能以“重新领取 Key”重置额度。云端任务到期、被主动释放、账号失效或模型配置变更时拒绝继续，仍允许查看合法本机内容。结束的内容测试沿用原有释放预占流程，不扣成功次数。

当前桌面仍是小范围内容测试入口；整场 PDF 正式用户流程及计次按阶段 F 接入。本阶段不开启 v2 完成交付结算。

## PDF 导出状态

阶段 B 的 Node 执行器可传入 `workflowStore`：导出设置、失败/取消状态、staging、最终目录、manifest 和 QA 证据同步保存到 export_profiles。重开读取原配置，`retryWorkflowPdf(staging,{workflowStore})` 只重试文件；个人/合订及是否附答案使用独立 exportId/profileHash，始终复用原内容，不再调用模型或重复扣次。最终验证通过的导出记录不可改写为失败或其他文件集合。

## 验证

```powershell
npm --prefix app run test:workflow-storage
npm --prefix app test
npm --prefix server test
```

存储专项先编译开发用 `workflow_store_probe`，通过独立进程和真实 SQLite 调用相同 Rust 源码，不使用 JSON 假数据库。强制进程退出验证 OCR、事实核验、挖空返回后的恢复，另覆盖进行中结果未知、事务回滚、记录损坏、账号隔离、过期租约、输入/模式/资料变化、跨模式共同分析缓存和原截止时间。PDF 集成覆盖失败后重开、文件复用、导出配置恢复、格式变化和零新增模型调用。界面测试使用明确合成 IPC，不等同于真实账号/模型验收。
